# Plan: compact_context tool + post-compaction user-message injection

## Objective

1. Bump `@opencode-ai/plugin` and `@opencode-ai/sdk` devDeps from `1.18.7` to `1.18.11` (the version bundled in the running opencode — `.opencode/node_modules`).
2. Add a `compact_context` plugin tool that an agent can call to compact its own session (v2 `session.compact` with v1 `session.summarize` fallback — see deviation log; the original spec said `session.command` but that path was proven dead).
3. Add `postCompactContinue` (boolean toggle) and `postCompactMsg` (string) configs. When on, after a compaction succeeds the plugin injects the configured text as a **real, persisted** user message via `experimental.compaction.autocontinue` (suppressing opencode's synthetic continue), so the agent resumes on the injected instruction. When off, no message is sent after compaction.
4. Persist this plan; implement with tests; verify live via a local plugin registration + `opencode run`.

## Decisions & constraints

- **Tool name**: `compact_context`. Always registered (no opt-out config for now — scope per request).
- **Compaction trigger**: primary = v2 `v2Client.v2.session.compact({ sessionID })` — the v2 client is built lazily at load from `@opencode-ai/sdk/v2/client` (client-only subpath; the full `/v2` entry pulls in cross-spawn/child_process and breaks `bun build` browser-mode) via `createOpencodeClient({ baseUrl: serverUrl?.href })`; `PluginInput.serverUrl` is provided. Fallback = v1 `client.session.summarize({ path:{id}, body:{ providerID, modelID, auto:true } })` — the ONLY working programmatic compaction path on 1.18.11 (calls `compactSvc.create` → `promptSvc.loop`; requires both model IDs; `auto:true` so the autocontinue hook fires). providerID/modelID come from the cached `experimental.chat.system.transform` model info (extended from the existing window cache); missing model info → honest `Compaction failed:` without calling summarize. The former v1 `session.command session.compact` fallback is DROPPED (verified dead: `UnknownError` on 1.18.11). NOTE: in SDK 1.18.11 the v1 `command`/`promptAsync`/`summarize` live on top-level `client.session.*`, NOT `client.app.session.*` (`App` only has `log`/`agents`); and v2 `compact` lives on `v2Client.v2.session` (Session3), not top-level `v2Client.session` (Session2 lacks it).
- **Post-compaction injection**: `experimental.compaction.autocontinue` hook. Always sets `output.enabled = false` (suppresses opencode's synthetic continue, so nothing is sent when off). When `postCompactContinue` is on: fire-and-forget `client.session.promptAsync({ path:{id}, body:{ agent: input.agent, parts:[{type:"text",text:opts.postCompactMsg}] } })` with a real user text part (`.catch` + log).
- **Real message, not synthetic**: unlike the transient warning injection, this must persist so the session loop processes it as the next user turn. Prefer `promptAsync` and tolerate races (ADR-001 already rejected mid-request store writes; the autocontinue point is a compaction boundary).
- **Config contract**: pure `resolveOptions(raw, env)` stays exported; env > file > default precedence; each bad value → `{ key, message }` problem. New keys go in `ContextWatchOptions`, `CONFIG_KEYS`, `DEFAULTS`. Env overrides `CONTEXT_WATCH_POST_COMPACT_CONTINUE` / `CONTEXT_WATCH_POST_COMPACT_MSG`.
- **Test seam**: `configPath` plugin option stays; tests import `src/index.ts` directly (never `dist/` — node:fs is stubbed in the bundle).

## Design

### Config
```
postCompactContinue: false          // boolean, CONTEXT_WATCH_POST_COMPACT_CONTINUE
postCompactMsg: "[context-watch] Session context was compacted. Continue your work from where you left off, keeping replies concise."  // string, CONTEXT_WATCH_POST_COMPACT_MSG
```

### compact_context tool
`execute(args, ctx)` calls `triggerCompact(ctx.sessionID)`:
1. v2: `await v2Client.v2.session.compact({ sessionID })` — v2 client built lazily once at load via `import("@opencode-ai/sdk/v2/client").createOpencodeClient({ baseUrl: serverUrl?.href })`; a missing v2 export degrades to the v1 fallback (never crashes plugin load).
2. On v2 failure/resolved-error: v1 `await client.session.summarize({ path: { id: sessionID }, body: { providerID, modelID, auto: true } })` using the per-session model info captured by `experimental.chat.system.transform`. If model info is missing for this session, return an honest failure without calling summarize.
3. Never throws — returns a `ToolResult` string ("Compaction requested." / "Compaction failed: <err>"); logs via `log()` helper.

Test seam: pluginOptions also accepts `createOpencodeClientV2(config) => V2CompactClient` (structural type `{ v2: { session: { compact } } }`) so tests inject a fake.

### autocontinue hook
```
"experimental.compaction.autocontinue": async (input, output) => {
  output.enabled = false;                      // always suppress synthetic continue
  if (!opts.postCompactContinue) return;       // off: no message sent at all
  client.session.promptAsync({ path:{ id: input.sessionID }, body:{ agent: input.agent, parts:[{type:"text",text:opts.postCompactMsg}] } }).catch(log);
}
```
Gating uses the loaded options; config is read once at load (existing behavior).

Walk: summarize handler `httpapi/handlers/session.ts:273-293` → `compactSvc.create()` (writes the real `type:"compaction"` part + would-publish `Event.Compacted`, `compaction.ts:513-536`) **then `yield* promptSvc.loop()` at line 291** → `prompt.ts:1346` `state.ensureRunning` → `run-state.ts:88-93` → `runner.ts:115-138`: the session is already `"Running"` (the main loop is executing our plugin tool), so `runner.ts:120-122` does `awaitDone(st.run.done)` — it JOINS the existing run fiber instead of starting a new one (`Deferred.await`).
